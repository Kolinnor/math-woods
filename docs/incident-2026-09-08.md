# Browser errors and monitoring, 8 September 2026

Production audit before these fixes: ten browser reports since midnight Paris
time, all before deployment of 5ec6ce7. Three reports were unsupported
`crypto.randomUUID` on Chrome 79. Five were anonymous repeating `Pk@ / Nk@`
stack overflows from Chrome on iPhone; two more reports from that browser had
insufficient context. No evidence links those anonymous frames to a particular
site component or to translation software.

The UUID failure is fixed in presence, citations, mathematician contributions
and editor draft receipts. Browser tests cover Chromium and WebKit with native
UUIDs removed, denied storage, and unavailable presence cryptography. Error
reporting now retains cross-window error objects and appends ErrorEvent's file,
line and column with URL query/hash removed. Reporting falls back to fetch when
a beacon is blocked. It does not suppress anonymous stack overflows.

Reading and opening details on `/concepts`, `/concepts/nombre-decimal`,
`/concepts/compas-collapsible`, and `/concepts/p-adic-valuation` did not reproduce
the stack overflow with Chromium or WebKit mobile emulation. WebKit on Windows
is not Chrome on a physical iPhone; that issue remains unconfirmed and needs a
reproducible sequence or richer diagnostics. Some navigation/prefetch requests
failed during the WebKit run, so this is not a blanket clean-browser result.

PostgreSQL recorded 78 duplicate achievement inserts, eight duplicate exposure
inserts and five duplicate trusted-user suggestions. These errors were caught;
inserts now use `skipDuplicates` so conflicts are handled without an error.
Only inserted rows cause notifications. The twelve-hour exposure cooldown and
translation grouping are unchanged. Tests cover repeated/concurrent calls and
propagation of real database failures.

The HTTP error dashboard and alert used a counter without a response-code label.
Both now read `caddy_http_response_duration_seconds_count`. The rule test checks
that sustained 5xx actually fires, healthy traffic reads zero, and absent data
is not misreported as healthy. These changes require a subsequent deployment.
